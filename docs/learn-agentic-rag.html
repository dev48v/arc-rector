🧭 Agentic RAG from zero

Chunking · embeddings · cosine · vector search · BM25 · citations · memory · guardrails · tracing · evaluation — every demo really runs, in your browser.

Four documents, one honest pipeline.

The corpus below is the real arc-rector/corpus/ — four documents it was built to answer questions about. Every panel runs on the one you edit: change the chunk size and the index is rebuilt, the vectors change, the ranking changes, the citations change and the eval score moves. Nothing here is pre-computed and nothing calls a server.

Why a model that knows everything still can't answer a question about your own documents. A language model only knows what was in its training data, and when you ask about a file it has never seen it does not go quiet — it produces a fluent, confident, wrong answer, because generating plausible text is the only thing it does.

Retrieval-augmented generation fixes this by never asking the model to remember: you chunk your documents into passages, turn each passage into a vector with an embedding model, keep those vectors in a vector database, and at question time you embed the question, find the nearest passages by cosine similarity, paste them into the prompt as numbered context, and demand that every sentence of the answer ends in a [n] marker pointing back at the passage it came from. That last step is the whole anti-hallucination lever — an answer you can click back to a source is an answer you can check, and a model that cannot find the answer in the context is told to say so instead of inventing one.

Around that core sit the four layers that make it survivable in production: memory so facts persist across turns, guardrails on the way in and the way out, a trace of every step because RAG failures are invisible without one, and an evaluation harness so you can tell "better" from merely "different". Everything below is the real pipeline from arc-rector — and every demo on this page actually computes: real chunking, a real deterministic embedder, real cosine, real vector search, real BM25, real citation binding, real traces, real scores. No API, no model download, no fakery.

Honest note. This is a hashing embedder — hash each word to a bucket, add a signed sub-linear count, normalise to unit length. It is real and deterministic (it is the hash adapter arc-rector's whole test suite runs on) but it has no semantic understanding: "car" and "automobile" hash to unrelated buckets. A trained neural embedder like Nomic Embed puts them next to each other. Everything downstream is identical — only the quality of the numbers differs.

These are proxies: token overlap and citation structure, not a judge. context_recall answers "did retrieval even fetch the right passage?" and faithfulness answers "is the answer made of words the context actually contained?" — separating a retrieval bug from a generation bug. Where this page simplifies — all of it, in one place
  • The embedder is a hashing trick, not a neural model. Real and deterministic, zero semantic understanding. Synonyms will not match. Nomic Embed (768-dim, Apache 2.0, 274 MB) is the real default.
  • Search is a linear scan, not HNSW. Correct at this size, useless past a few thousand chunks. Real stores build a navigable small-world graph and accept approximate answers.
  • There is no LLM. Answers are extracted sentences with citation markers attached; the ungrounded example is a written-out illustration, clearly labelled as such.
  • No reranker. Arc Rector's real pipeline fetches 12 candidates with the fast bi-encoder and reranks to 4 with a cross-encoder. Here the fetch is the ranking.
  • Memory is regex extraction, so it stores contradictions side by side instead of reconciling them.
  • Guardrails are patterns, and the eval metrics are overlap proxies rather than a judged score.

    Define the interfaces before you pick a vendor
    
        
    Every level of the stack — inference, vector store, embeddings, memory, guardrails — gets one small abstract class, and the pipeline only ever talks to those. This is not architecture astronautics: it is the only way to answer "did switching to Qdrant actually help?", because you can swap one layer while everything else stays byte-identical.
    
        
    from abc import ABC, abstractmethod

class Embeddings(ABC):
    dim: int
    @abstractmethod
    def embed_documents(self, texts: list[str]) -> list[list[float]]: ...
    @abstractmethod
    def embed_query(self, text: str) -> list[float]: ...

class VectorStore(ABC):
    @abstractmethod
    def ensure_collection(self, dim: int) -> None: ...
    @abstractmethod
    def upsert(self, chunks, vectors) -> int: ...
    @abstractmethod
    def search(self, vector, top_k: int = 5) -> list[Retrieved]: ...

# every adapter normalises to COSINE, higher-is-better - so a swap
# changes the storage engine, not the ranking

    Parse anything into plain text with provenance
    
        
    Ingestion is where silent data loss happens: a PDF parser that drops table cells or reorders a two-column layout poisons every answer downstream and never raises an error. Whatever parser you use, carry the source path and title onto every document — you cannot cite what you cannot name. Collect failures instead of aborting the batch, or one broken file stops the whole ingest.
    
        
    from pathlib import Path

def load_documents(loader, sources):
    docs, failures = [], []
    for src in sources:
        try:
            doc = loader.load(str(src))          # Docling / Unstructured / plaintext
            if doc.text.strip():
                docs.append(doc)                 # doc carries .source and .title
            else:
                failures.append((str(src), "parsed to empty text"))
        except Exception as exc:
            failures.append((str(src), f"{type(exc).__name__}: {exc}"))
    return docs, failures
# report failures loudly - a silently skipped document is an
# unanswerable question three weeks later

    Chunk on paragraph boundaries, with overlap
    
        
    This is the exact function driving panel 1. Pack whole paragraphs greedily rather than cutting at a fixed offset, because a paragraph is already a semantic unit; only hard-split when a single paragraph exceeds the limit, and then on sentence ends. The overlap carries the tail of one chunk into the next so a fact that straddles a boundary is still intact somewhere. Give each chunk a content-addressed id so re-ingesting unchanged text overwrites in place instead of duplicating.
    
        
    import hashlib, re
_PARA = re.compile(r"\n\s*\n")

def chunk_text(text, chunk_size=900, chunk_overlap=150):
    if chunk_overlap >= chunk_size:
        raise ValueError("overlap must be smaller than chunk_size")
    blocks = []
    for para in _PARA.split(normalise(text)):
        if para.strip():
            blocks.extend(_split_long(para.strip(), chunk_size))

    chunks, current = [], ""
    for block in blocks:
        if not current:
            current = block
        elif len(current) + 2 + len(block) <= chunk_size:
            current = f"{current}\n\n{block}"
        else:
            chunks.append(current)
            carry  = _overlap_tail(current, chunk_overlap)   # snapped to a word
            current = f"{carry}\n\n{block}".strip() if carry else block
    if current:
        chunks.append(current)
    return chunks

def stable_chunk_id(doc_id, ordinal, text):
    return hashlib.sha1(f"{doc_id}:{ordinal}:{text}".encode()).hexdigest()[:32]

    Embed — and get the prefixes right
    
        
    Nomic Embed v1/v1.5 are instruction-prefixed: stored text must be embedded as search_document: … and a query as search_query: …. Omitting them raises no error and produces no obviously broken output — it just retrieves slightly worse documents forever. That is the most expensive class of bug in this field, and the only thing that catches it is an eval harness. Start with the offline hashing embedder so your tests need no model at all.
    
        
    class NomicEmbeddings(Embeddings):
    dim = 768                                   # fixed by the model

    def embed_documents(self, texts):
        return [self._call(f"search_document: {t}") for t in texts]

    def embed_query(self, text):
        return self._call(f"search_query: {text}")    # DIFFERENT prefix

# offline fallback: the hashing trick - no model, no network, deterministic
def hash_embed(text, dim=512):
    vec = [0.0] * dim
    for token, count in Counter(tokenize(text)).items():
        i, sign = bucket(token, dim)
        vec[i] += sign * (1.0 + math.log(count))      # sublinear tf
    n = math.sqrt(sum(v * v for v in vec))
    return [v / n for v in vec] if n else _unit_fallback(dim)

    5
    Store the vectors — and refuse to mix dimensionalities
    
        
    A collection is created with a fixed dimensionality. Nomic gives 768, MiniLM 384, Jina v2 small 512 — so changing the embedding model always means re-ingesting. If you let two models' vectors into one collection you get confident nonsense with no error, which is why ensure_collection raises instead. Store the chunk text in the payload alongside the vector so retrieval is one round trip, not a search followed by a document fetch.
    
        
    from qdrant_client import QdrantClient, models

class QdrantStore(VectorStore):
    def ensure_collection(self, dim):
        if self.client.collection_exists(self.collection):
            got = self.client.get_collection(self.collection)
            existing = got.config.params.vectors.size
            if existing != dim:
                raise ValueError(
                    f"collection holds dim {existing}, embedder gives {dim}: "
                    f"re-ingest with --reset")
            return
        self.client.create_collection(
            self.collection,
            vectors_config=models.VectorParams(
                size=dim, distance=models.Distance.COSINE))

    def upsert(self, chunks, vectors):
        points = [models.PointStruct(
                    id=str(uuid.UUID(c.chunk_id)),   # Qdrant ids: int or UUID only
                    vector=list(v),
                    payload={"text": c.text, "title": c.title, "source": c.source})
                  for c, v in zip(chunks, vectors)]
        self.client.upsert(self.collection, points=points)
        return len(points)

    Retrieve wide, then rerank narrow
    
        
    A bi-encoder is fast because document vectors were computed in advance — but the query and the document are never seen together, so the ranking is approximate. The standard fix is two-stage: pull ~12 candidates cheaply, then let a cross-encoder score each (query, document) pair jointly and keep the best 4. You get most of a cross-encoder's accuracy for a fraction of its cost, because the expensive model only ever sees a handful of documents.
    
        
    def retrieve(deps, question):
    vector = deps.embeddings.embed_query(question)      # search_query: prefix
    hits   = deps.store.search(vector, top_k=deps.fetch_k)   # fetch_k = 12
    return deps.reranker.rerank(question, hits, deps.top_k)  # top_k = 4

# hybrid: fuse the semantic ranking with BM25 by reciprocal rank fusion.
# RRF needs no score normalisation - it only uses positions.
def rrf(rankings, k=60):
    fused = {}
    for ranking in rankings:
        for rank, doc_id in enumerate(ranking, start=1):
            fused[doc_id] = fused.get(doc_id, 0.0) + 1.0 / (k + rank)
    return sorted(fused, key=fused.get, reverse=True)

    Number the context so citations can bind to it
    
        
    Citations are not decoration bolted on afterwards — the numbering has to exist in the prompt so the model has something to point at. Pack entries until the character budget runs out, then renumber so markers are always contiguous from 1: a citation the model can see must correspond to text the model actually received. After generation, keep only the citations the answer really referenced, and check for markers that point at nothing.
    
        
    def format_context(hits, max_chars=6000):
    citations, blocks, used, budget = build_citations(hits), [], [], max_chars
    for hit in hits:
        cite = by_id[hit.chunk.chunk_id]
        entry = f"[{cite.marker}] {cite.title} -- {cite.source}\n{hit.chunk.text}"
        if len(entry) > budget:
            if budget < 200: break
            entry = entry[:budget].rstrip() + " ..."
        blocks.append(entry); used.append(cite); budget -= len(entry)
    # renumber 1..n over what actually FITTED, then rewrite the markers
    return renumber(blocks, used)

MARKER_RE = re.compile(r"\[(\d{1,2})\]")

def prune_citations(answer, citations):        # show only what was cited
    markers = {int(m.group(1)) for m in MARKER_RE.finditer(answer)}
    return [c for c in citations if c.marker in markers] or list(citations)

def dangling_markers(answer, citations):       # markers pointing at nothing
    valid = {c.marker for c in citations}
    return [m for m in used_markers(answer) if m not in valid]

    Write the system prompt that makes refusal legal
    
        
    Without an explicit escape hatch a model will always answer, because answering is what it was trained to do. Give it a exact sentence to emit when the context is insufficient, and it will use it. Notice the three separate demands: answer only from the context, cite every factual sentence, and never invent a marker number.
    
        
    SYSTEM_PROMPT = (
    "You are a precise research assistant. Answer ONLY from the numbered context "
    "provided. Every factual sentence must end with a citation marker like [1] or "
    "[2] identifying the context entry it came from. If the context does not "
    "contain the answer, say exactly: I don't know based on the provided documents. "
    "Never invent a citation number that is not in the context. Be concise.")

def build_prompt(question, context, memories=()):
    return (f"{format_memories(memories)}"
            f"Context:\n{context or '(no documents retrieved)'}\n\n"
            f"Question: {question}\n\n"
            f"Answer using only the context above, with [n] citation markers:")

    Wire the turn as a state machine — guard, recall, retrieve, generate, guard, remember
    
        
    Now assemble it. Guardrail rejection is a first-class terminal state, not an early return, so a blocked turn still produces a traceable, uniformly shaped result. Memory reads and writes are wrapped in try/except because memory is an enhancement — a memory outage must degrade the answer, never fail it. Trace every stage: a RAG bug is almost always "the wrong chunks were retrieved", and without a trace you cannot see that the retrieval was wrong rather than the model.
    
        
    def run_turn(deps, question):
    with tracer.span("guard_input"):
        guard_in = deps.guardrails.check_input(question)
        if not guard_in.allowed:
            return blocked_answer(question, guard_in.reason, guard_in.validator)

    with tracer.span("recall"):    memories = recall(deps, question)
    with tracer.span("retrieve"):  hits     = retrieve(deps, question)

    context, citations = format_context(hits, deps.max_context_chars)
    prompt = build_prompt(question, context, memories)

    with tracer.span("generate", input=prompt, model=deps.model):
        raw = deps.inference.complete(prompt, system=SYSTEM_PROMPT)

    with tracer.span("guard_output"):
        guard_out = deps.guardrails.check_output(raw, context=context)
        if not guard_out.allowed:
            return blocked_answer(question, guard_out.reason)

    answer = assemble(question, guard_out.text or raw, hits, citations, memories)
    with tracer.span("remember"):  remember(deps, question, answer.text)
    return answer                  # .citations = only the ones actually used

    Build the eval set before you tune anything
    
        
    Eight hand-written question/answer pairs with references is enough to start, and it is the difference between engineering and vibes. Score retrieval and generation separately — context precision and recall tell you whether the right passage was even fetched; faithfulness and answer relevancy tell you what the model did with it. Treat absolute numbers from a small local judge as directional and the delta between runs as the real signal. Then change exactly one knob at a time.
    
        
    from ragas import evaluate, EvaluationDataset
from ragas.metrics import (faithfulness, answer_relevancy,
                           context_precision, context_recall)

samples = [{"user_input": q,
            "response":   answer.text,
            "retrieved_contexts": [h.chunk.text for h in answer.retrieved],
            "reference":  gold}                     # hand-written
           for q, gold in GOLD_SET]

report = evaluate(EvaluationDataset.from_list(samples),
                  metrics=[faithfulness, answer_relevancy,
                           context_precision, context_recall],
                  llm=local_judge)      # same Ollama model, no vendor key

🎉 That's the whole pipeline.

      
An LLM hallucinates about your documents because it never saw them, so RAG stops asking it to remember and starts handing it the evidence. Chunk on paragraph boundaries with overlap; embed each chunk into a vector (and get the model's prefixes right); store them in a vector database that indexes for approximate nearest-neighbour search; at query time retrieve by cosine similarity, fuse with BM25 because keyword search still wins on names and codes, and rerank the shortlist with a cross-encoder. Number the surviving chunks into the prompt so citations can bind to real sources, and give the model an exact sentence to say when the context does not contain the answer. Then wrap it: memory for what persists across turns, guardrails on input and output, a trace of every stage, and an eval set so you can prove a change helped. 👉 The code: github.com/dev48v/arc-rector — nine levels, every one swappable, every default open source and running with no API key.
